# Current Feature: Vocabulary — Learn Session

## Status

Not Started

## Goals

Spec: `docs/features/vocabulary-learn-session.md` (scoped slice of `docs/PAWLINGO_VOCABULARY_PLAN.md` §9/§39). Deliver in discrete, independently reviewable parts — user wants to check in between parts, not one large dump.

1. **Service layer**: add `setStatus(wordId, status)` to `VocabularyService` interface + `mockVocabularyService` implementation (mirrors existing `setFavorite`). `realVocabularyService` keeps throwing via `realServiceUnavailable()`, same as every other method.
2. **Session composition logic**: pool selection (`listVocabularies({ topic, difficultyLevel, size: 6 })` filtered to not-yet-saved words, min 3 / target 6) + distractor selection (3 other words from the same result set, same topic/difficulty) — pure data logic, no UI yet.
3. **Screen flow UI**: 3-stage per-word flow (Presentation → Recognition MC → Context MC), correct/incorrect feedback (icon + text, never color-only), progress indicator (`3 / 6`, text only).
4. **Session summary screen**: completion stats (never claims `MASTERED`), calls `setStatus(wordId, "LEARNING")` for all session words, "Về trang chủ" / "Học thêm" actions.
5. **Entry points**: new route `/vocabularies/learn?topic=&difficultyLevel=`; secondary "Học từ mới" action on `/home`'s existing topic chips; "Học N từ mới theo bộ lọc này" action on `/vocabularies` when enough unsaved words match current filters. No changes to existing routes, primary nav labels, or filter UI.
6. **Empty/error states**: reuse existing emoji+message+"Thử lại" convention; <3 unsaved words matching filter → don't start session, show "Không đủ từ mới cho bộ lọc này."; mid-session navigation-away is an accepted loss (no persistence in this slice).

Explicitly out of scope this feature (see spec's "Out of scope" section): Review/SRS sessions, Curriculum (Course/Unit/Lesson), Recall/Production stages, listening/collocation exercises, AI explanation/pronunciation scoring, adaptive difficulty, real backend integration.

## Notes

- Design direction: focused exercise screen, not a marketing page — `design-taste-frontend` skill's Section 13 excludes dense product UI from its Section 11 landing-page workflow, so that 4-step process does not apply here (same conclusion as `/home` and `/vocabularies`). Reuse existing tokens only (coral accent, `rounded-3xl`/`rounded-full`, `buttonVariants({variant:"pop"})`, existing focus-ring convention) — no new colors/radii/shadows, no decorative motion.
- Open defaults from the spec, not yet confirmed: session size = 6, minimum pool = 3, "Học thêm" behavior (start another session with same filter vs. return to topic picker) — proposed as reasonable defaults, adjust if they feel wrong once tried.
- User preference for this feature: implement part by part (roughly matching the numbered Goals above), pause for review between parts rather than delivering everything at once.
